# 原神 圖鑒

離線可用的原神資料圖鑒：**角色 134 名、武器 246 把、聖遺物 63 套**，含技能天賦、命之座、推薦配裝、有效詞條、畢業面板參考與培養素材。

## 怎麼看

直接雙擊 **`index.html`** 用瀏覽器開啟即可（不需要架伺服器、不需要連網）。

上方四個分頁：**角色 / 武器 / 聖遺物 / 培養計算**。前三個各自有獨立的篩選、搜尋與排序。
手機上圖鑒一排顯示四個。

### 角色

篩選：元素／武器／星級／定位／反應體系／技能功能／成長屬性／性別／體型／年齡層／地區

- 同一列多選＝聯集（選「風＋冰」= 風或冰）；不同列＝交集
- **反應體系**與**技能功能**是「全部符合」：同時選「減抗」和「治療」= 兩者都有的角色
- 技能功能下方的「來源」可切 **主動／被動／命座**，例如「減抗 + 主動」只列出靠 E／Q 直接減抗的角色

點卡片開角色詳情，六個分頁：

| 分頁 | 內容 |
| --- | --- |
| 資料 | 元素、武器、定位、體型、突破加成、反應體系、技能功能標籤 |
| 面板 | **Lv90 基礎面板**、**有效詞條**（沙／杯／冠／副詞條）、**畢業面板參考** |
| 天賦 | 普攻／戰技／爆發／固有天賦全文（保留遊戲原本的重點顏色、冷卻與耗能） |
| 命座 | C1～C6 全文，關鍵命座金框標出並附說明 |
| 配裝 | 推薦聖遺物、推薦武器（**可點進去看詳細資料**）、關鍵命座 |
| 素材 | 突破 6 階素材、天賦 1→10 素材、合計與摩拉 |

### 武器

246 把（已排除 24 個武器外觀）。篩選類型／星級／副屬性，排序可依基礎攻擊或新增順序。
詳情含 Lv90 基礎攻擊與副屬性、**精煉 1～5 階全文**、突破素材，以及「哪些角色推薦這把」（可點回角色）。

### 聖遺物

63 套。詳情含 2 件／4 件套效果、五個部位的名稱與圖鑒文字，以及「推薦給哪些角色」。

角色頁的推薦聖遺物與武器都帶圖示，**點下去可以看該裝備的完整資料，看完按左上角「← 返回 ○○」回到原本的角色**（可以一路往下點，返回會照原路退回來）。

### 培養計算

多目標的素材計算機，設定會存在瀏覽器裡。

- 選角色加入目標，每個目標可設定**角色等級**（現在 → 目標）、**三個天賦各自的等級**、**武器與武器等級**
- 預設是「Lv1／天賦 1」練到「Lv90 ↑／天賦 10」，每一欄都能改；等級選單的 `↑` 代表已完成該階突破
- 右邊列出所有需要的素材，填入目前擁有的數量後會即時算出還缺多少
- **多個角色需要同一種素材會自動合併計算**
- **低階素材多出來時會自動用 3→1 合成往上補**（寶石、怪物掉落、天賦書、武器突破素材都吃這個規則），並標示「合成補 N」
- 角色經驗書與武器精鍛礦由所需經驗換算，摩拉一併算出

## 三種資料的可信度不一樣

**1. 官方原始資料（可直接信）**
元素、武器、星級、體型、地區、生日、上線日、天賦全文、命座全文、突破加成、武器數值與精煉效果、聖遺物套裝效果、所有培養素材。來自 Project Amber 的遊戲解包資料。

**2. 由官方數值計算（公式明確）**
- **Lv90 基礎面板**：初始值 × 官方 90 級成長曲線 ＋ 第 6 階突破加成。與遊戲內數值完全一致（驗證過胡桃 = 生命 15552／攻擊 106／防禦 876）。
- **武器 Lv90 基礎攻擊與副屬性**：同樣算法。
- **畢業面板參考**：用一組固定假設算出來的**參考值，不是精算**。假設是「聖遺物 5 件滿級、主詞條照有效詞條、副詞條給 25% 主屬性、帶推薦武器第一把與推薦聖遺物的 2 件效果」，全部集中在 `tools/build-stats.js` 的 `ASSUME`，不同意直接改。實際面板會因武器精煉、命座與隊伍增益而不同。
- **雙暴目標 70%/200%、充能需求**：前者是社群通用標準，後者依元素爆發耗能與定位推算，實際仍要看隊伍充能環境。

**3. 自動從技能原文擷取（規則產生，可能有漏）**
- **技能功能標籤**（減抗、團隊增傷、攻擊力加成…）：逐句掃 855 條天賦＋792 條命座原文比對關鍵字，並標出來源是主動、被動還是命座。「加成」類只在句子出現隊友範圍字樣時才標記，所以胡桃自己加攻擊力不會被算成團隊增益；也排除了「自己抗性降低」這種自身減益。規則在 `tools/build-data.js` 的 `RULES`。
- **成長屬性與有效詞條**：從技能原文找「基於…生命值上限／防禦力／元素精通」判斷傷害吃哪個屬性，再依定位與爆發耗能推出沙杯冠與副詞條優先序。少數規則判不出來的（心海不吃暴擊、妮露吃生命…）寫在 `tools/build-stats.js` 的 `OVERRIDE`。

**4. 人工整理（主觀，歡迎改）**
定位、機制標籤、反應體系、推薦聖遺物、推薦武器、關鍵命座，集中在 `tools/roles.js` 與 `tools/builds.js`。
2026 年後上線的 30 名角色在配裝頁會顯示 ⚠，那些是依技能文本與同期裝備推斷的。

配裝有自動驗證器 `node tools/validate.js`，會檢查：

- 聖遺物／武器名稱是否真的存在，武器是否誤填成武器外觀
- **武器類型是否與角色相符**（法器角色不能推薦雙手劍）
- **套裝條件是否成立**：例如樂園遺落之花只算綻放體系、翠綠之影只給風角色、海染硨磲只給有治療的角色、黑曜秘典只給納塔夜魂角色
- 有無重複項目

條件表寫在 `tools/validate.js` 的 `COND`，改配裝後跑一次就知道有沒有寫錯。

**關於「年齡層」**：用官方**模型體型**分類（成女／成男＝成年體型，蘿莉／少女／少年＝未成年體型），不是實際年齡考據。

## 檔案結構

```
index.html              圖鑒主頁（唯一要開的檔案）
data/
  characters.js/.json   角色（含天賦、命座、面板、詞條、素材）
  weapons.js/.json      武器
  artifacts.js/.json    聖遺物
  materials.js/.json    素材總表（511 種）、合成鏈（121 條）、等級經驗表
  characters.csv        Excel 用（UTF-8 BOM，不含天賦全文）
  _raw*                 所有原始 API 回應與成長曲線，可自行核對
images/
  icon/ splash/         角色頭像與立繪
  element/              七元素圖標
  weapon/ artifact/     武器與聖遺物圖標
  item/                 培養素材圖標
tools/
  roles.js              ★ 定位／機制標籤／一句話特色（手動維護）
  builds.js             ★ 反應體系／聖遺物／武器／關鍵命座（手動維護）
  build-stats.js        ★ 面板計算假設 ASSUME 與詞條例外 OVERRIDE
  build-data.js         產生角色資料，並自動擷取技能功能標籤
  build-equip.js        產生武器／聖遺物資料、培養素材與合成鏈
  validate.js           配裝驗證器（名稱、武器類型、套裝條件）
  fetch-detail.sh       下載角色天賦／命座
  fetch-equip.sh        下載武器／聖遺物明細
  fetch-images.sh       下載角色頭像／立繪
  fetch-equip-icons.sh  下載武器／聖遺物／素材圖標
  update.sh             一鍵更新（以上全部跑一遍）
  serve.js              可選的本機 http 伺服器（node tools/serve.js → localhost:5177）
```

## 更新

出新角色或新裝備時，在 Git Bash 執行：

```bash
bash tools/update.sh
```

接著手動補新角色的 `tools/roles.js` 與 `tools/builds.js`，再跑 `node tools/build-data.js` 與 `node tools/validate.js`。
其餘（天賦、命座、功能標籤、基礎面板、有效詞條、畢業目標、培養素材）都是自動產生的。
